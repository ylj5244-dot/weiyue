用于 Apple Silicon 和 Intel Mac（macOS 14 或更新版本）的微博群聊阅读工作台。当前版本 1.0.12（构建 18）。宽阅读栏顶部压为群信息和常用工具两行，同步详情、成员和日期筛选集中在下拉菜单，阅读位置入口移到右下角。当前群关注阅读、随内容收放的消息背景、分类设置、长图和侧栏网页预览、微博表情、存储清理、书签、收藏、AI 讨论、三套日夜皮肤及后台同步均保留。

本轮使用方式见 [1.0.12 紧凑工具栏说明](compact-reader-v112.md)，完整更新见 [1.0.12 发布说明](releases/v1.0.12.md)，验证见 [1.0.12 验收记录](verification-v112.md)。此前的阅读与预览改进保存在 [1.0.11 说明](reading-refinement-v111.md)，标题与皮肤见 [1.0.9 说明](reading-title-skins-v109.md)。

## 阅读与整理

1. 在应用里的微博官方页面扫码登录，点击左侧「我的群聊」旁的「管理」，勾选需要同步的群，再点「保存同步选择」。左侧群列表用于切换阅读；关闭某群同步会保留已有消息、书签和收藏。首次自动补齐至少 500 条本地消息（不足时以微博实际返回为准），可继续「加载更早 500 条」。已选群每 4 秒检查新消息，多页积压会继续追补。阅读一个群时，其他已选群也继续同步；左侧群名旁显示本机尚未查看的新消息数量，点击该群清除角标并恢复原阅读位置。计数跨重开保留，重复同步与历史补载不重复计入；这是微阅自己的提醒，不等同于微博官方未读数。
2. 切换「专注阅读」。不显示头像，直接展示加粗放大的成员名称。同人同一天连续多条发言形成一个浅色框，跨人或跨日分开；原生皮肤的发言块按当前筛选后的阅读顺序以浅蓝、浅绿、浅杏三种底色依次循环；青绿与 Claude Code 皮肤在框内逐条轮换三种底色，同一成员连续消息也分色，日间、夜间分别适配。名称或成员 ID 完整匹配「粉丝群」的系统通知在这里隐藏，原始记录不删除，官方聊天不受影响。消息左侧的选择框与对应正文的起始位置对齐。框内保留逐条选择和操作；消息操作依次为「复制 → 从这里阅读 → 加入书签 → 加入收藏 → 翻译成中文 → 加入讨论」，其中翻译项只在原文含英文时显示。鼠标悬停或键盘焦点进入消息后，操作按钮在卡片右上方浮现，不再常驻正文下方，也不使用消息「更多」菜单。续读点、书签和单条收藏都有选中状态，再次点击即可取消。点书签按钮直接保存完整年月日、时分秒和原消息快照；取消后移入书签的「最近删除」，重新点击优先恢复已有记录，保存失败后的重试不会重复添加。左侧最近书签和「书签」页面均可添加或编辑备注，只修改选中书签的备注，保留原日期、时间和消息快照。已有书签的消息常驻显示「已加书签」提示；手动续读点有独立标签。书签数量没有人为上限，左侧最近书签只显示当前群，点击可定位原文；左侧导航中的「书签」页面可按群筛选，选择「所有群聊」查看全部。
3. 每个群分别保存三个独立位置：消息上的「从这里阅读」设置固定的**手动续读点**，设置另一条消息时替换；再次点击当前续读点，只清除这个手动位置，自动阅读进度和临时返回位置不变。正常阅读滚动只更新**自动阅读进度**，切群或重开时自动恢复；点击「最新」或定位其他消息前记录**临时返回位置**。阅读区右下角提供「最新」，并按可用位置显示「回到手动续读点」及「返回跳转前」，点击定位并高亮原消息；多选时避开底部操作栏。点击群名旁的同步状态可查看详细进度、记录范围，以及「立即同步」和「加载更早 500 条」。手动续读点不会被滚动、切群或重开覆盖；多个固定位置可使用不限数量的书签。旧版本的自动进度和返回位置保留，不会猜测哪一条曾是被覆盖的手动点。顶部显示「已保存至本机」后，当前修改已收到磁盘保存确认。
4. 用「全部成员」按姓名或成员 ID 查找，只勾选需要的消息，再点「加入收藏」，也可用消息上的收藏开关保存单条消息。单条收藏一键保存，不弹出命名窗口；再次点击可取消并移入资料库的「最近删除」，重新点击优先恢复已有记录。单条收藏开关不修改包含这条消息的多条合集。保存完成后留在当前阅读位置；之后从左侧「资料库」查看持久保存的收藏，重命名、导出，或加入右侧讨论。「资料库」支持单条删除、勾选批量删除、搜索后全选；删除后可撤销或在「最近删除」恢复，原聊天、文件和 AI 讨论仍保留。若只需立即讨论，可直接点「加入讨论」；这不会自动建立收藏。
5. 拖动两条竖向分隔线调整左侧群聊和右侧 AI 宽度，中间阅读区随之变化，各栏内容随宽度调整。到达当前布局的最小宽度后，分隔线停止继续收窄；扩大侧栏也会为阅读区和另一侧可见栏保留最低宽度。也可用 Tab 聚焦分隔线，再按左右方向键微调；按住 Shift 可大步调整，Home 或双击分隔线恢复该侧默认宽度，仍受最小宽度和可用空间约束。顶部按钮可分别收起、展开两侧栏。宽度与手动收起状态会跨重启保留；窗口不足以容纳三栏时会临时收起侧栏，为正文保留空间。自动收起不会覆盖保存的宽度和手动收起状态，窗口放大后恢复。

顶部「外观」可明确选择「跟随系统／日间／夜间」，重开会记住偏好。跟随系统时即时响应 macOS 外观变化，手动选择则固定为相应皮肤；官方聊天网页保持微博自身内容与样式。

阅读区与右侧「一起读懂」标题旁使用同样的紧凑 **Aa 字号**下拉。阅读区可选择 14、16、18，保持本次打开期间的选择；右侧 AI 可选择 14、16、18、20、22，默认 14。调整后立即生效，随当前账号保存在本机，重开后恢复；独立于中间阅读区字号。讨论正文、实时回复、思考内容和来源随之调整，未登录时暂不能保存字号。

在「设置 → 重点关注人员」中，按已见成员的姓名或 ID 搜索并添加，也可手动输入完整 ID 和可选备注名。编辑完点击「保存」；失败时保留草稿，可重试或取消。添加、修改和取消关注都在这里完成，消息上不再提供关注按钮。关注按成员 ID 识别，同名不同 ID 不会混淆；当前账号各群共用，账号之间独立，最多 200 人，默认名单为空。关注成员显示更宽的红色边标、姓名强调和常驻「★ 重点关注」徽标，日间、夜间均有对应配色，原有三色发言块保留；书签和手动续读点继续使用金色。关注名单在本机保存，未配置 AI 或 AI 正在运行时也可管理。

当前群的专注阅读提供「全部发言 / ★ 只看关注」切换；左侧不再单列关注视图。关注成员在全部发言中也有醒目的边线与底色，连续发言只在组首显示姓名和标志。「只看关注」可结合日期、关键词和消息类型筛选，不覆盖未筛选时的群阅读位置。

成员和日期条件在工具栏「筛选」菜单中设置；「管理重点关注人员」也在该菜单中。生效时，工具栏下方显示条件、匹配数及「清除筛选」。点击菜单外部或按 Escape 关闭，宽度不足时常用工具换行保留。

阅读区搜索框旁可选「全部、链接、图片、文件、视频」，控件随阅读栏宽度调整。关键词同时匹配消息正文、附件名称和链接地址；与成员及日期条件共同生效。搜索仅覆盖本地已保存记录。专注阅读时，按本人账号 ID 识别自己的消息并靠右显示，不按昵称猜测身份。消息背景随内容、字号和附件尺寸收放；连续发言使用统一宽度。完整的撤回通知在专注阅读中隐藏。

## 联网搜索

右侧 AI 输入框上方的「联网搜索」可手动开关，默认关闭，选择随当前账号保存在本机。开启后使用现有 DeepSeek 官方 API Key，先搜索公开网页再交给模型回答；当前支持 `https://api.deepseek.com` 及其标准 `/v1` 地址，兼容转发服务不会自动获得此能力。

搜索词取自本次提问前 128 个 UTF-16 单元，不附带所选群聊、图片或文档；模型仍接收你明确提交的资料和本次讨论。界面显示搜索、整理网页、模型思考和回答状态。搜索是服务方单独计费的调用，实际价格和权限以 DeepSeek 账户为准。

回答下方保留来源链接、网页发布时间（如有）、检索时间和摘要。当前搜索引用为 `[网页1]` 等；继续讨论时，旧来源使用独立的 `[历史网页轮次-序号]`，避免与新网页混淆。关闭搜索后仍可讨论已经保存的来源，但不会把它们当作本次新检索结果。来源和开关在重开后保留。无结果或失败会明确提示「未经联网核实」，不保证信息永远最新或完整。网页内容仅作参考，不覆盖个人偏好和当前讨论要求。

时段总结只在最终合并时检索一次，各批次不会重复搜索。检索结果最多 5 个来源，模型收到每个来源至多 5,000 个 UTF-16 单元，超过部分明确标注截断。

## 翻译与文档解读

先在设置中填写兼容 Chat Completions 的 HTTPS API 地址和自己的 Key，点击「刷新可用模型」选择真实模型 ID，再「测试连接」。已有 Key 可使用上方授权入口。连接测试只发送固定文字「只回复 OK」，不发送群聊。Key 按微博账号和 API 地址分别存入 macOS 钥匙串。

- **翻译单条聊天：**原文含英文时，消息上显示「翻译成中文」；英文词句、中英混合文字及 AI、GPU、NVDA 等缩写均可显示入口，只有中文、数字、标点、网址、邮箱或显式代码格式的消息不显示。点击后使用当前选定的模型，译文直接显示在这条原消息下方，可展开、收起、取消或重新翻译。请求仅包含该条原文和翻译指令，不带右侧讨论或其他资料，也不启用联网搜索。原聊天不会被覆盖，当前讨论不受影响。完成的译文随账号保存；原文改变后不再显示旧译文。行内译文最多保留 100 条，原文与译文合计不超过 100 万字符，超出时淘汰较早记录；未完成的部分不会作为完整译文保存。
- **批量翻译聊天：**勾选多条消息后点「批量翻译」，结果仍在右侧独立讨论中展示，译文与所选来源一起保存，可从讨论历史恢复。
- **解读或翻译图片与文档：**鼠标移到卡片上，或用 Tab 聚焦卡片，图片顶部或文件行右侧出现「解读」「翻译」和「更多」。点解读或翻译即准备当前这个附件，并在右侧建立新讨论自动执行，不需再点发送。新讨论不带其他聊天正文或未选附件；沿用当前模型、长期偏好和联网搜索开关。图片默认优先由支持视觉的模型直接阅读原图，也可在设置中切换本机 OCR。读取方式、页数、缺失或截断信息保留在资料卡中。旧收藏可点对应文件的「重新读取」更新方式。
- **附件更多操作：**「更多」包含「加入讨论」「另存为…」「在访达中显示」「到微博查看」。加入讨论只准备当前附件，不自动发送。操作条预留独立位置，不遮住图片或文件名；文件处理状态及失败重试不会随鼠标移开而消失。
- **导入本地资料：**点右侧「本次讨论资料」旁的「文档」，选择文档或图片。应用会把副本保存到本地附件目录，并按当前模型准备直读文件或提取正文。支持 PDF、Word（DOCX、DOC）、RTF、ODT，以及 TXT、Markdown、CSV、JSON 等文本和常见图片格式；表格、演示文稿可先导出为 PDF。
- **保存与追溯：**点右侧「保存资料」，把所选消息、附件提取文字与关联讨论保存到「资料库」。群聊资料可「定位原消息」，导入文件可「在访达中显示」。批量译文和 AI 回复可从讨论「历史」重新打开；单条行内译文随原消息显示。只加入右侧、尚未发送或保存的资料不保证重启保留。

「加入讨论」和文件导入只在本机准备资料；点击右侧的**发送、翻译或解读**，或点击附件卡片的**解读、翻译**时，才把对应资料提交到配置的服务。单条行内翻译按上面的独立请求范围执行。已知视觉模型直接接收图像；支持 PDF 文件的模型接收 PDF，DeepSeek Flash 接收 PDF 原始页面图像，不经过 OCR。Word、文本等在本机提取正文。兼容服务的图像/PDF能力可以按服务文档在设置中明确开启。

输入框 **Enter 发送，Shift+Enter 换行**，中文输入法选字不会误发。「联网搜索」和「深度思考」横向并列，点亮表示开启，再点击变灰关闭。模型支持思考开关时，按钮状态对应实际请求；固定推理或未确认能力的模型明确显示限制，不能假装已经关闭。运行时显示真实阶段、耗时、思考内容（服务提供时）与回答增量；不伪造百分比。取消、断流、账号切换会保留提问和已收到的内容。服务一次性返回或输出截断会单独提示。

模型刷新每次直接请求服务的 `/models`，绕过缓存，显示其实际返回的 ID。DeepSeek 官方截至 2026-10-18 的 `deepseek-flash` 对应 **DeepSeek-V4.1-Flash-1017**，版本更新可能沿用同一 API ID，不伪造一个服务未提供的模型名称。

## 个人偏好与快捷提问

从「设置 → 个人偏好」打开长期偏好库。可按「写作风格／展示格式／其他要求」添加多项内容，并随时修改、停用、排序或删除；点击「保存偏好库」后应用到后续讨论提问。初始长期偏好为空，不会擅自填入推测的个人风格。偏好按微博账号保存在本机，同一账号各群聊共用；切换模型或重开应用后仍保留。未配置 AI 或 AI 正在运行时也可查看、编辑和保存；修改作用于后续请求，不改动已经发出的请求。

每次讨论发送都会带上当前启用的长期偏好，包括新讨论；单条行内翻译使用固定翻译指令。讨论中的优先级为：**本轮明确提问 > 长期偏好**。临时要求直接写进本轮对话输入框；右侧不再提供「本次要求」入口。旧版本保存的临时要求仍保留在历史数据中，但恢复旧讨论后也不会再自动注入新请求，时段总结和后续追问同样如此。修改或删除偏好会影响后续请求，不会重写已有回复。模型仍可能执行不完全，可在本轮提问中纠正。

偏好库的「快捷提问」页可以自定义按钮名称和完整问题，并增删、修改、停用及调整顺序。点击输入框上方的快捷按钮只填入文字，可继续修改后发送。删除所有快捷提问后保持为空，不会在重开后恢复默认按钮。

长期偏好与本轮提问在发送时会随请求提供给所选 API 服务；未发送的快捷提问不会自动提交。偏好最多 100 项，快捷提问最多 50 项，每项内容最多 12,000 字符，全部标题与内容合计最多 60,000 字符；超限会明确提示，不会悄悄截断。个人偏好保存失败时保留编辑草稿并恢复原来生效的设置，可重试或取消。

右侧「讨论 → 历史」支持逐条删除和清空全部讨论。删除会移入「最近删除」，可恢复，关闭重开仍保留恢复入口。删除当前讨论会回到新讨论；原聊天、书签、收藏资料、个人偏好和快捷提问不会被删除。AI 工作或保存期间暂不能删除，保存失败会提示并保留原记录。

## 按时段总结群聊

在「专注阅读」工具栏点击 **时段总结**，选择开始、结束日期与时间（精确到分钟），可补充希望重点梳理的内容，再点「开始 AI 总结」。范围按本机时区解释，包含结束分钟内的消息；若选择当前分钟，只统计开始加载时刻之前的消息。这里读取当前群的整个时段，不受阅读区搜索、成员或日期筛选影响。

窗口先显示本地已有数量和「待核对」。开始后从微博最新历史连续读取，直到越过起始时间或收到明确的历史终点，才标记为「已核对完整」。不以本地最早、最新消息日期推断中间没有缺口。遇到限流、断网、顺序异常或读取上限，会说明原因及已取得数量，可以重试；只有明确点击「仅总结已加载的 N 条」，才会用不完整记录生成总结，并在结果中保留提示。单次核对最多 200 页、10 分钟，超限也不会当作完整。

消息过多时自动分批梳理，再逐层合并；显示当前批次、模型状态与增量文字。开始任务后可点击弹窗外、按 Escape 或收起按钮返回主界面，任务继续运行，右侧保留阶段、数量、批次及停止入口。收起不等于取消；明确点击停止才会取消。后台运行限应用仍打开时，退出应用会按原有逻辑中断并保存已完成内容。每一批都包含任务开始时启用的个人偏好和本次具体问题，后者优先，不自动附加旧讨论保存的临时要求。输入超限或模型输出被截断会明确停止，不会把遗漏的批次算作完成。已完成的分批结果和讨论来源会保存，失败或重开后可查看并重新生成。

总结中的 **[消息编号]** 可回看对应原文。即使原文尚未归档，也可查看保存在讨论中的来源快照，不改变原阅读位置。全部来源按每页 20 条浏览，避免一次渲染大量消息。总结、来源、完整性信息和具体问题随讨论保存在本机，关闭重开后可从右侧「历史」恢复；后续追问基于已生成的摘要，不重复发送整个时段。

时段总结覆盖消息文字与附件名称；不会自动读取或上传整段聊天中的图片、文档正文。需要解读具体文件时，仍从原消息单独加入讨论。加载阶段取消时，已取得的记录只保留在当前窗口供选择部分总结；创建讨论后才持久保存来源。点击「开始 AI 总结」会将该时段的消息提交给已设置的 API 服务，并可能产生多次模型调用。

## 文件读取范围

- AI 单文件不超过 25 MiB（25 × 1024 × 1024 字节）。普通附件打开、下载仍以 200 MB 为上限。
- **直接读取：**一次最多 20 份文件；原始 PDF 最多 50 页，PDF 页面图像最多 12 页，超限明确拒绝，不自动截取前几页。图片会按视觉输入限制缩放，紧凑 PNG 保留原像素。多帧图片只处理第一帧，并提示限制。
- **本机提取：**每个文件最多提取 80,000 字符。PDF 最多处理前 50 页，其中需要 OCR 的扫描页最多 12 页；时间上限或无法识别的页面也可能使读取提前结束。界面会显示实际页数、截断和缺失提示，较大文件请拆分后继续读取。
- 图片 OCR 仅识别文字，可能有错字或遗漏；不代表已经理解图表、照片或排版。多帧图片只识别第一帧。文档中的图片、图表、批注、页眉页脚及复杂排版也可能未包含，应对照原文件核实。
- 每次 AI 资料总量上限为 16 万字符，超出会提示减少或分批讨论，不会在提交时悄悄截断。服务本身还可能有更小的上下文限制。
- 受保护、禁止复制、损坏、不支持或没有可读文字的文件会给出明确提示。可改用可复制的 PDF、清晰图片或 UTF-8／UTF-16 文本重试。

## 本地文件与数据

图片在阅读区显示紧凑缩略图；附件可通过相应入口打开、下载或在访达中显示。点击图片或视频打开独立预览窗口，点击内容以外的空白处、按 Esc 或点关闭即可退出。长图默认按窗口宽度从顶部显示，可滚动阅读、切换「查看全图」或「适应宽度」；普通图片完整适配窗口。图片支持「−／+」「100%」、触控板捏合和放大后拖动，双击在自动适配与原始大小之间切换；关闭视频会停止播放。链接与文档只显示紧凑标题行：链接点击后在右侧内置浏览器打开，正文和图片根据栏宽调整，可切回「原网页」；PDF、Word 等文档使用 macOS 快速查看预览。右上角分别提供「用默认浏览器打开」或「用默认应用打开」；关闭预览可回到原 AI 讨论。内置浏览器支持后退、前进和刷新，使用独立的临时会话，部分需要登录或系统不支持的内容可交给默认浏览器或应用。设置中的「存储与自动清理 → 查看本地保存位置」显示完整路径，提供复制和打开文件夹。

资料位于 `~/Library/Application Support/WeiboReader/`，按账号分别保存；附件及导入文件位于其「附件」子目录。「另存」文件保存在自行选定的位置，相应访达入口会优先定位另存文件。聊天资料以原子写入方式保存，并保留上一份有效备份；首次成功保存也会建立备份。可在「设置 → 存储与自动清理 → 清理本地缓存」选择当前群或所有群，分别清理文字、图片、文档；先预览数量，再确认。已被标记、收藏、AI 讨论或阅读位置引用的资料自动保护。文件移到系统废纸篓，文字保留恢复快照，可撤销上一次清理。清理过的旧消息不会被自动重新归档；已清图片通过明确的重新下载操作恢复。需要实际释放磁盘空间时，由用户自行清空废纸篓，之后文件可能无法恢复。

「存储与自动清理」还显示本机资料总占用和聊天记录、附件缓存、备份等分类，统计范围为微阅资料目录内所有账号；当前账号消息数量单独列出。定时自动清理默认关闭，可选保留最近 1、2、3 或 4 天。启用并保存后在关闭设置时检查，运行期间每小时检查一次，退出后暂停，下次启动或唤醒补查。按消息时间计算滚动天数；书签（含最近删除）、收藏、讨论引用、阅读锚点、当前未发送资料、正在阅读或勾选的消息、正在预览的资料及手动导入文件保留。自动清理直接删除符合条件的本地记录与无引用缓存，不进入废纸篓，不生成撤销副本；同时压缩当前账号备份，旧记录不会由自动同步重新填回。微博上的原消息不受影响；失败会显示状态并保留待重试项。

保存失败会明确提示；退出前会取消仍在读取或生成的任务、保留已建立讨论的提问，并等待保存。重新打开后可从讨论历史继续或重试。损坏文件会保留，不能恢复时会停止加载，避免用空数据覆盖。

## 接入与验收边界

官方聊天使用微博自己的网页，保留网页原有界面和操作。本地书签与微博官方未读数相互独立；进入官方群聊可能按微博自身逻辑清除官方未读数。没有向群内发送测试消息；发送、转发、撤回、上传、语音和通知等尚未逐项完成实际验收，因此不宣称与手机客户端全部功能完全相同。

仅归档勾选群的消息。历史与增量读取使用官方网页登录会话和只读 GET，暂停、限流、错误有状态提示。新消息采用轮询，睡眠、断网和服务限流会带来延迟；恢复后从已知消息继续追补。搜索范围是本地已保存消息，不代表全部历史，也不保证所有官方消息类型都能归档。
