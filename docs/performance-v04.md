# 0.4 阅读性能修复

2026-10-18，合成数据基准；未读取用户聊天记录或凭据。

## 已确认的原因

0.3 每次消息同步、筛选和切换群聊都创建当前群全部消息卡片（每条包含头像、选择框、多个操作按钮和附件）。滚动事件对全部卡片调用查询和位置读取，查找第一条可见消息。后台保存每次克隆全库，并把每个中间版本逐个排队写盘。群统计和未筛选消息列表重复全库遍历、验证及排序。

## 修复

- 可变高度虚拟列表：保留完整消息索引，界面只挂载视口及前后缓冲区。正文搜索、成员/时间筛选仍覆盖完整本地消息。
- 高度前缀索引支持任意位置跳转；图片加载或窗口改宽后，以消息 ID 和行内偏移校正。加载更早历史和新消息加入均保持原阅读锚点。
- 同步批次在 120 毫秒窗口内合并绘制；搜索输入在 120 毫秒内合并。
- 只测量已挂载行，滚动期间每帧最多执行一次位置采集；未跨出当前范围且布局未变时不重建 DOM、不重测整段高度。
- 已验证消息建立群/时间索引，群数量与无筛选列表可直接读取。
- 后台保存合并未执行的中间版本；每个调用方仍须等覆盖其修改的版本实际保存后才完成。不同账户不合并。显式保存和退出屏障仍可等待落盘确认。
- 去掉 `postMessage` 前多余的全库 JSON 克隆；原生桥本身同步取得发送快照。

## 可重复验证

运行 `node scripts/benchmark-reader.cjs`。本机本轮示例结果：

| 项目 | 旧路径 | 新路径 |
|---|---:|---:|
| 5,000 条消息、900 像素视口、80 像素估算行高的消息卡片数 | 5,000 | 29 |
| 同一账户 100 次积压保存的实际执行次数 | 100 | 2 |
| 无筛选列表查询中位耗时 | 4.259 ms | 0.0002 ms（索引建立后） |
| 5,000 条全量关键词查询中位耗时 | — | 0.4839 ms |
| 每次保存额外全量克隆中位耗时 | 2.743 ms | 移除 |

这些数据用于比较计算量和节点数，不代表原生窗口实测帧率；实际首次索引建立、排版、磁盘速度及 API 网络等待另计。窗口列表会按实测行高调整，挂载条数随消息长度变化。

`tests/performance.test.cjs` 覆盖完整搜索、可变高度索引、首次深历史恢复、第 4,980 条跳转、500 条历史插入、图片增高、快速滚动、筛选到离屏单条、保存合并及保存失败传播。所有样例内容为虚构。


## 原生 WebKit 集成与滚动测量

运行 `bash scripts/test-desktop-ui.sh`，将生产 HTML/CSS/JS 复制到临时目录，由独立、非持久 WKWebView 加载。原生桥全部使用合成 `ready/save/AI progress/cleanup` 回复；测试不会打开真实应用、访问账号资料或调用外部 API。

2026-10-18 本机实测：5,000 条合成消息（每 13 条包含图片，预览由本机合成 PNG 提供），1488 × 1056 窗口，连续 100 次滚动，`requestAnimationFrame` 间隔中位 **17 ms**、P95 **18 ms**；输入到下一帧中位 **17 ms**、P95 **23–25 ms**（最近两轮）。滚动过程最多 **29** 张消息卡片，初始 **28** 张、最终 **16** 张。此测量来自离屏原生 WebKit 窗口，不代表官方微博网页、真实图片下载及所有硬件条件下的帧率保证。

测试会断言 100 次滚动确实离开第 500 条并前进超过第 550 条，自动保存的消息 ID 与实际可见消息一致；还会断言「查看最新」实际显示最后一条消息。早期仅记录帧间隔和节点数的测试没有验证内容真正前进，因此漏掉了 WebKit 在 DOM 被临时移入 fragment 时立即把 `scrollTop` 钳制为 0 的问题。补上断言后稳定复现失败；修复为每次 DOM 替换后恢复该次滚动位置，普通滚动及最新跳转均通过。纯 JS 布局测试也模拟了这种即时钳制，作为快速回归检查。

同轮集成测试验证图片实际解码、第 500 条阅读位置恢复、含图片的实时同步保持同一条消息及像素偏移、第 4,000 条书签跳转、收藏单删撤销和批删恢复、输入法回车不误发、Shift+Enter 不发送、Enter 发送、模型思考与回答增量显示、清理预览/执行/撤销，以及同步重放无法重新导入已清理文字，且没有前端脚本错误。同步测试还发现并修复了卡片上方间距被非负持久化偏移丢弃的问题：渲染锚点保留 signed `visualOffset`，持久化 `offset` 的协议不变。

主题扩展验收使用独立窗口的 `aqua` / `darkAqua` 外观，不改系统设置：检查真实 `computedStyle` 的页面背景、面板、文本变量及正文颜色；显式日间覆盖原生夜间，显式夜间覆盖原生日间，跟随系统模式响应原生外观变化。日间背景为 `rgb(237, 240, 243)`，夜间为 `rgb(32, 36, 40)`。通过真实选择框触发 `saveAppearance` 后，清除测试站点的 localStorage 并重新加载页面，确认原生 `ready` 恢复夜间偏好，同时恢复之前自动保存的第 617 条消息及行内偏移。所有保存仅在测试进程内存中进行。
