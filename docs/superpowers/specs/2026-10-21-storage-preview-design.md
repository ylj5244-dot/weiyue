# 微阅 1.0.10：存储、响应速度与右侧预览

用户已明确要求五项修改，本设计据此确定常规实现选择：存储在设置二级页，自动清理默认关闭，天数 1–4；链接和文档改为标题式条目，点击在右侧预览，图片居中且保留完整比例。当前基线为 1.0.9，Git 提交 7b6c720。

## 存储管理

设置里的「存储与缓存」打开二级管理页。显示本机资料目录实际占用及聊天/账号数据、附件、备份/清理恢复、其他文件分类；另显示当前账号聊天数量。统计在后台进行，失败显示错误而非零值。现有分类手动清理迁入该页，仍保留范围、预览、保护引用与撤销。明确手动清理的文件移至废纸篓，实际释放需清空废纸篓。

自动清理按账号保存，默认关闭，可选择保留最近 1、2、3、4 天（默认 3 天）。以消息时间和当前时刻的滚动 24 小时天数判断，未知或未来时间不删除。应用启动/恢复及运行期间定期检查，退出/休眠时不承诺执行。只清理过期、未被书签/收藏/讨论/阅读位置保护的聊天记录与可再下载缓存；导入文件不属于自动清理范围。删除后不被自动同步重新归档。已有清理保护逻辑继续适用，也保护最近删除中的引用和当前尚未提交的讨论材料。

自动清理先保存移除后的状态，再删除符合条件的缓存文件；不能因文件删除失败丢失用户收藏。自动清理不生成无限增长的完整恢复快照，不把所有文件移入废纸篓冒充释放空间。界面明确自动清理不可撤销、本机缓存范围、最近运行与处理结果；用户开启才生效。运行中的 AI、导入、保存及手动清理应互斥，失败可重试。

## 操作性能

使用 6000 及 10000 条合成记录重现书签和续读点延迟，分别衡量 JS 操作反馈与原生持久化。点击后即时显示目标状态及保存中；保存成功才宣告已保存；失败局部回滚，不覆盖并发的阅读进度或其他操作。修复重复全文件解析与无效页面重绘，保持原子写入、数据验证、备份、旧版本拒绝与损坏保护。

## 附件与右侧预览

链接和文档采用紧凑标题行，显示实际文档名/链接，避免「附件／文件」巨卡及重复正文。保留鼠标悬停/键盘焦点下的解读、翻译和更多操作。链接及文档标题可点击；网址进入右侧独立 WKWebView，文件用原生嵌入式预览支持 PDF、Word 与文本格式。网页隔离于本地应用桥接，不读应用密钥或本地资料。

右侧预览暂时覆盖 AI 区，提供关闭/返回讨论、网页后退/前进/刷新、当前位置和顶部「用默认浏览器打开」；文件则为「用默认应用打开」。关闭预览恢复讨论与草稿，AI 任务不被清空。原生预览随右侧拖拽/隐藏/窗口尺寸变化，弹窗或账号切换时不遮挡或遗留上一账号资料。远程 URL 只允许 HTTP(S)，文件只接受已验证的应用附件路径；下载/不支持预览时显示失败与外部打开入口。

## 图片外观

图片采用完整比例、居中对齐、对称留白；缩略图不裁切、不拉伸，长图限制展示高度，点击仍可查看原图和缩放。多图使用居中网格，宽窄布局与日夜模式均检查。保留加载失败重试以及附件操作，不以巨大固定空白卡片包裹图片。

## 验证与交付

新增过期边界、受保护共享附件、账号隔离、自动清理开关/重复运行/失败、统计符号链接边界、预览导航与退出、5000+ 消息反馈的测试。完整 Node/Swift 测试、必要原生 UI 及日夜窄宽截图验收后生成 1.0.10（构建 16）通用安装包和源码包。测试仅使用合成资料，不对真实账号执行清理，不向群聊发送消息。保留 MIT 与简洁 emoji README。
