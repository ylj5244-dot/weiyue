# 1.0.0 时段总结验收

日期：2026-10-18。版本统一采用 1.0.x，本次为 1.0.0。

## 实现范围

- 专注阅读中的「时段总结」支持开始、结束日期及分钟，按本机时区处理，包含结束分钟。当前分钟以开始加载时刻为上限，拒绝未来时段。统计与读取不受当前搜索或成员筛选影响。
- 从微博最新历史连续核对到起始边界，不把本地最早、最新时间当成完整性依据。显示实际数量、页数、完整性和失败原因。中止、断网、限流、顺序异常、重复游标、超时或读取上限均不能标为完整；明确选择后才可总结已有部分。
- 单次加载最多 200 页、10 分钟。读取任务独立取消，不篡改原历史游标、实时同步游标、阅读锚点和清理屏蔽记录。新取到但未归档的消息仅作为总结来源快照保存。
- 消息按真实序列化大小分批，超长消息完整拆分；先生成各批摘要，再逐层归并。全部请求带当前启用偏好、当前讨论临时要求和本次明确提问，优先级依次提升。每批成功后等本地保存完成再继续。
- 模型截断、内容过滤中止、空响应、不收敛或保存失败均停止，不将该批算作完成；已保存批次可查看和重新生成。取消不会继续发送下一批。
- 总结引用可以回看已归档原文或来源快照，保留返回阅读处。来源每页 20 条；已保存分批结果按需渲染。快照不会伪装成已归档消息，也不会写成无效阅读锚点。
- 保存全部来源、总结、原始问题、临时要求、覆盖信息及中断状态。重开恢复并保留引用。后续追问携带已有摘要，避免重复发送整段原文。
- 本次批量总结处理文字及附件名称，不自动读取或上传图片、文档正文。文件仍使用原有单独加入 AI 的流程。
- 新增讨论历史单条删除、清空与最近删除恢复。删除活动讨论返回新讨论，恢复不擅自切换。删除记录继续保存快照、临时要求及关联，原聊天、收藏、阅读标记、个人偏好和快捷提问均保留。

## 验收边界

上述 AI 与历史分页测试均使用合成数据或模拟服务响应，不访问真实 API Key，不把真实群聊交给外部模型，也没有向群内发送测试消息。它们验证请求与界面流程，不等同于真实微博所有历史可取或模型语义总结质量的保证。线上记录不可取得时，应用必须继续明确显示不完整。

原有官方发送、撤回、语音等功能的实测边界继续沿用 README，不宣称全部完成验收。
