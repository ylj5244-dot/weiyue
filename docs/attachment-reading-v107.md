# 微阅 1.0.7 交互约定

本次范围来自用户已确认的附件方案及三张界面反馈图。

- 图片、文档均提供悬停或键盘焦点出现的「解读」「翻译」「更多」；解读和翻译直接准备当前单个附件，在右侧新讨论执行。更多保留「加入讨论」「另存为…」「在访达中显示」「到微博查看」。加入讨论只准备资料，不自动发送。
- 浮动条使用附件顶部独立的紧凑位置，显隐不改变高度、不压住预览或文件名。更多采用原生菜单，避免被阅读区裁切。处理状态和失败重试保持可见。
- 两个字号入口统一为紧凑原生下拉，但仍分别控制中间正文与右侧 AI。保留阅读区原 14／16／18，AI 原 14／16／18／20／22。AI 继续按现有方式持久化，阅读区继续原有会话内设置。
- 连续发言逐条保留原消息及原文换行；正文占满可用宽度。操作条不再通过浮动挤窄后续正文；同组首条与后续条统一正文字号、行高和相邻正文间距。
- 图片、视频使用独立预览窗口；点击内容以外的空白处或按 Esc 关闭。图片提供放大、缩小、适应窗口、100% 按钮，支持捏合缩放和放大后拖动。关闭视频时停止播放并释放播放器；切换账号或退出应用时关闭预览。文档仍使用快速查看。
- 不改变真实账号、登录态、已有记录或旧版交付文件。版本为 1.0.7，构建 13。

执行顺序：复现连续发言几何问题 → 并行改附件、字号和消息布局 → 实际 WKWebView 验证按钮、文件范围、账号隔离、失败重试与重开 → 全套逻辑／原生测试 → 双架构构建及发行校验。所有验收使用临时合成数据。
